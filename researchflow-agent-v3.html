PROCESS

一个科研整理，往往要走好几步

科研不止于"得到一篇笔记"，更在于厘清关注点、追溯文献依据，并把精读沉淀为真正能复用的研究资产。

FIRST · 读论文

读论文 · 定关注

在 Zotero 读 PDF、高亮，手写 3–5 个关注点关键词。研究方向由你定义——Agent 不替你选题，只对齐你的关注。

SECOND · 理依据

理依据 · 标状态

告别模型补写。Agent 按 19 字段 + 八段骨架补全笔记，每条结论标注「论文事实 / 概括 / 建议 / 未报告」，重要信息回到原文核查。

LAST · 沉淀资产

沉淀资产 · 多处复用

远离低效堆砌。结构化笔记存入 Obsidian，被周报、组会 PPT、方法白皮书等下游 Skill 直接读取复用——一次精读，处处调用。

CORE MECHANISM

做科研整理，不能只是聊天

从字段结构化、笔记骨架到事实核查与安全边界，ResearchFlow Agent 帮你真正攻克"文献 → 方法"这一环。

01

19 字段结构化

9 个通用元信息 + 10 个领域字段，统一 frontmatter，跨论文可比较、可检索。

02

八段笔记骨架

论文画像 / 完整精读 / 关键选择 / 对本文启发 / 参数速查 / 可引用原文 / 高亮，结构稳定。

03

信息状态分离

每条提取内容标注 事实 / 概括 / 建议 / 未报告，抑制科研幻觉，让重要信息回到原文。

04

安全规则：只追加不重写

绝不覆盖你已整理的原始研究内容；新增默认追加新节或另建新文件。

05

本地优先

论文 PDF、未发表想法、实验参数默认存本地（Zotero + Obsidian），不自动上传外部服务。

06

通用核心 + 领域可定制

核心流程与领域无关；仅替换领域字段与示例包，即可用于任何学科方向。

PIPELINE

标准工具链路，一次跑通

四环相扣：文献源 → 知识库 → CODEX + Skill 执行引擎 → 成果复用。这一整套流程，就是 ResearchFlow。

Zotero

读 PDF、高亮、生成全文缓存，提供 citekey 与条目。

Obsidian

Zotero Integration 按模板导入，产出带 9 元信息字段的笔记。

CODEX + Skill

在 CODEX（OpenAI）中调用 ResearchFlow 的各类 Skill：读全文、补笔记、生成组会 PPT……也可由 Claude 等模型驱动同一套流程。

↓
下游复用

Skill 直接输出周报 / 组会 PPT / 方法白皮书等成果，复用同一份笔记。

没有 Zotero 也能用：手动在 Obsidian 建笔记、手填字段、粘全文，再交给 Agent——结构不变。

DOWNSTREAM

组会 PPT · 从笔记到上台，丝滑生成

组会 PPT Skill 将结构化笔记直接转为可放映的 Slide，覆盖两类核心场景——文献汇报与个人科研进度汇报：先生成 Deck Plan 确认结构，再成稿带讲者备注。
